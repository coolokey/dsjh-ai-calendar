# 附件二、AI 行政應用資安與倫理自我檢核表 - 填答指引

> 說明：教育局線上報名系統將此部分列為必填檢核項目。評審首重資訊安全與合規性，以下為本專案之具體檢核狀態與建議填答理由：

---

### 一、資訊安全評估

| 檢核項目 | 具體檢核標準 | 建議勾選 | 說明與具體防護對策 |
| :--- | :--- | :---: | :--- |
| **1. 資安規範遵循** | 系統開發與運行是否遵循資通安全管理法？ | **☑ 是** | 本系統部署於 Google 雲端基礎架構（Google Apps Script 與 Google Workspace 教育版），後端由 Google 安全資料中心託管，完全符合我國資通安全管理法及教育體系資安規範。 |
| **2. 安全防護措施** | 系統是否已採取必要的安全措施，包含資料加密、存取控制與異常監控？ | **☑ 是** | 1. **傳輸加密**：前後端通訊全程採用 HTTPS / TLS 1.3 協定加密。<br>2. **金鑰保護**：Gemini API Key 僅儲存於 Google Apps Script 伺服器端環境變數（Script Properties），前端網頁絕無金鑰洩漏風險。<br>3. **存取權限**：會議刪除機制採用 SHA-256 雜湊演算法加密驗證，防止非權限人員誤刪。 |
| **3. 新型威脅防禦** | 系統架構與開發人員是否具備警覺提示注入攻擊及深度偽造等新型資安威脅之防護能力與意識？ | **☑ 是** | 1. **Prompt Injection 防護**：採用結構化輸出模式（Response MIME Type: `application/json`）與明確系統指引（System Instruction），限定模型僅能輸出符合欄位規格之 JSON 物件，阻絕惡意指令逃逸。<br>2. **輸入清理**：前端及後端皆對輸入字串進行格式驗證與 HTML 轉義防護（防範 XSS）。 |
| **4. 資安通報機制** | 是否已建立事件應變機制，約定一旦發生資料外洩或安全事故，須立即通報並承擔相應責任？ | **☑ 是** | 已納入學校現行資安事件應變作業要點，若發現異常流量或未授權變更，將第一時間通報學校資訊組長及教育局資安通報平台進行溯源與阻斷處置。 |

### 二、風險分級與人類監督評估

| 檢核項目 | 具體檢核標準 | 建議勾選 | 說明與具體防護對策 |
| :--- | :--- | :---: | :--- |
| **1. 權益影響評估** | 系統產出是否涉及直接影響學生或教職員的重大權益、安全、教育或職業機會？（如：學籍異動、獎懲建議、資源分配、績效評估）<br>*註：若為「是」，則屬高風險* | **☑ 否** | 本系統定位為「**行政時程輔助工具**」，僅協助排程時間萃取、場地預約登記與公告文字草擬，**絕不涉及**學籍、成績、考績、獎懲或資源分配等任何實質權益決策。 |
| **2. 機密性評估** | 此 AI 應用是否需處理機密文書、個人身分資料或高度敏感性資料？<br>*註：若為「是」，則嚴禁使用外部 AI 平台* | **☑ 否** | 系統規範僅處理公開或半公開之校內會議時程資訊（如：開會名稱、時間、地點、承辦處室）。**嚴格限制並宣導同仁禁止將涉及個資（身分證字號、個案病歷、機密公文原檔）輸入 AI 解析模組**。 |
| **3. 風險級別初判** | 根據應用目的及權益影響程度勾選級別：<br>• 廣泛應用 (最小風險)<br>• 審慎應用 (中低風險)<br>• 嚴格限制 (高風險)<br>• 不可應用 (嚴格禁止) | **☑ 廣泛應用**<br>*(或 審慎應用)* | **建議勾選「廣泛應用 (最小風險)」**：<br>本應用屬於「自動排程、文字摘要與格式轉換」之日常業務情境，性質與拼字檢查相同，屬於最小風險之安全可靠應用。即使勾選「審慎應用」，本系統也完全落實「人工監督與最終核可」之規範。 |
| **4. 人類參與決策** | 無論風險等級為何，最終決策者（業務承辦人）應對 AI 產出負起最終責任。是否已確認將進行最終審查、校正與決行的人員？ | **☑ 是** | 系統落實 **「AI 預擬、人工微調」** 核心原則。AI 萃取之會議資料僅回填至預覽表單，**必須由承辦同仁親自確認檢視無誤後，主動點擊「確認預約」方會正式寫入資料庫**，確保人類始終掌握最終決策權。 |
| **5. 智財權與合規** | 使用 AI 產生內容時，是否須確保不侵犯第三方著作權，並遵守版權及人格權相關法規？ | **☑ 是** | AI 所產出之會議議程與通知文案均基於校內事實資訊進行語法重組，未引用未經授權之第三方著作，完全符合著作權法及公務倫理規範。 |
